PtpIpCamera connects an Arduino-compatible board to a Canon EOS camera over WiFi, with a small C++ API for exposure, capture, and bracketing.

01 / What you can build

A few controls.
A lot of possibilities.

01

Exposure in familiar units

Set aperture as an f-number, shutter speed in seconds, and ISO as an integer. The library translates supported exposure steps into Canon’s wire values.

camera.setAperture(5.6f);
02

Capture and bracket

Run autofocus and release the shutter with one call. For bracketing, choose 3, 5, 7, or 9 shots, their EV spacing, and which exposure parameter changes first.

camera.initiateCapture();
03

Keep up with the camera

Call poll() from your loop to read property changes from physical dials. Optional log callbacks and a 512-entry diagnostic buffer help when a session misbehaves.

camera.dumpDiagnostics(Serial);

02 / Software bracketing

One scene.
A few exposures.

The sequence starts from a saved base exposure and calculates each shot’s EV offset. You choose the order, adjustment priority, and per-axis limits.

04 / Get started

From sketch
to shutter.

  1. Set up the camera

    Use Remote Shooting / EOS Utility mode. Connect your board to the camera’s WiFi network.

  2. Add the library

    In PlatformIO, add the repository URL to lib_deps. For Arduino IDE, download the repository ZIP and use Sketch → Include Library → Add .ZIP Library.

  3. Make it yours

    Replace the SSID, password, and IP below with the values from your camera. Check return codes before capture, and keep calling poll().

Documented hardware setup
Adafruit ESP32-S3 Feather + Canon EOS 5D Mark IV. Other boards and camera models need their own validation.

Try the interactive SerialShell example ↗
platformio.ini
lib_deps =
    https://github.com/seemantadutta/PtpIpCamera
your_first_capture.ino
#include <WiFi.h>
#include "PtpIpCamera.h"

PtpIpTransport transport;
PtpIpSession session(transport);
Canon5DMkIV camera(session);

void setup() {
  Serial.begin(115200);
  WiFi.begin("YOUR_CAMERA_SSID", "YOUR_PASSWORD");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
  }

  // Use the IP shown by your camera.
  if (camera.begin("192.168.1.2") != CAM_OK) return;

  if (camera.setAperture(5.6f) != CAM_OK) return;
  if (camera.setShutterSpeed(1.0f / 100.0f) != CAM_OK) return;
  if (camera.setISO(400) != CAM_OK) return;

  CameraResult result = camera.initiateCapture();
  Serial.println(cameraResultStr(result));
}

void loop() {
  // Poll roughly five times a second.
  static uint32_t lastPoll = 0;
  if (millis() - lastPoll >= 200) {
    lastPoll = millis();
    camera.poll();
  }
}

05 / Project notes

Where things stand.

A small open-source library, with room to improve. These are the practical limits of the current implementation.

Camera support is model-specific

Canon5DMkIV is the only concrete model subclass in this repository. Other Canon bodies may need initialization or capture changes. Use initiateCapture() for autofocus and shutter release; standalone releaseShutter() can return busy on an idle body.

Capture completion needs further work

The real Canon implementation registers a capture-completion callback, but its regular poll() path currently handles property changes only. Don’t depend on onCaptureComplete to confirm that an image has finished writing.

Check bracket results on real hardware

A bracket sequence can continue after a completion wait times out. Exposure restoration is attempted, but restoration errors aren’t returned. A CAM_OK result doesn’t guarantee every image finished writing or that the base settings were restored.
